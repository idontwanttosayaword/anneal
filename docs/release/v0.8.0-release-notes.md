# Anneal v0.8.0 — Developer Preview 8

This page is the release notes for `v0.8.0`, and the source text for the GitHub
Release body of the same tag.

Anneal runs chains of coding agents on your own machine. You queue tasks on a
board, and each one is planned, reviewed, implemented, verified and merged
unattended, on the Codex and Claude subscriptions you are already signed in to.
A chain only stops when a human decision is needed, and everything it did stays
observable and durable: tasks, agents, repository and file grants, isolated run
records, provider event streams, human questions, review gates and git delivery,
in one workflow.

**What this release is for.** The same envelope as the previews before it:
evaluating Anneal on a machine you own, against repositories you are willing to
have an agent write to. It is not a production install.

## What changed since v0.7.0

The headline is that you now decide who runs each step of a workflow, and Linux
is a platform Anneal is verified on rather than one it is expected to work on:

- **Staffing profiles decide who runs each step.** A task template carries
  several staffing profiles with exactly one default. A profile holds one entry
  per step, keyed on the step's exact `outputKind`, naming the agent that runs
  it and — for an optional step — whether it is included or skipped. A step can
  now be declared optional in the template, so skipping one no longer means
  cloning the template. Instantiation resolves each step as dispatch override,
  then the selected profile, then the canonical binding, and a `Staffing: <name>`
  line in a brief picks a profile by name. `Project.skipOptionalSteps` is
  removed: that decision now lives per step, in a profile.
- **A Workflows console edits all of it.** `/workflows` walks templates, then
  profiles, then a per-step editor with an assignable-agent picker and an
  include/skip toggle. The New Task panel gained a profile selector and a
  preview that resolves override over profile over canonical and marks the
  steps that will be skipped, before the chain exists.
- **Agents are identified by role, and named for what they are.** An agent's
  canonical identity is its `canonicalRole` rather than its name, and the
  canonical agents are renamed in place to `role-model-effort` slugs.
  `POST /agents/:agentId/duplicate` copies one. Review steps are renamed for
  what they do instead of for the model that runs them. Reassigning a task is
  refused with `409` while that task has an active Run.
- **Linux is a maintainer-verified platform.** The runner's admission, workspace
  restore and PATH mechanisms work there as they do on macOS, `RUNNER_PATH` is
  optional with a per-platform default, and Anneal's services install and deploy
  as systemd units. Runner identities can be namespaced with
  `AGENTOS_RUNNER_ID_PREFIX` so a second machine's runners do not collide with
  the control plane's.
- **A host can run its own gate slots.** `RUNNER_GATE_LOCAL_SLOTS` (and
  `AGENTOS_GATE_LOCAL_SLOTS`) let a host contribute a fixed number of local
  merge-gate slots, tried before its configured remote worker and accounted per
  runner account. `jq` is now a declared gate-worker prerequisite, and a worker
  without it says `GATE NOT RUN` rather than producing an empty FAIL.
- **A Run survives more of what the outside world does to it.** A provider
  capacity refusal is a transient external fault rather than the agent's
  failure, and a fix step resumes from its own salvaged attempt. A Codex Run
  resumes inside the Run after a provider disconnect. An external transport
  fault refunds the attempt instead of spending a retry silently, an automatic
  retry publishes to the branch its task declares, and the first mirror clone of
  a repository on a machine has its own time budget with a documented pre-seed
  path.
- **The merge tail has an operator exit and a patient train.** A regression FAIL
  inside base-drift recovery reopens through
  `POST /tasks/:taskId/merge-tail/repair`. A merge train that finds the lease
  contended waits for it, then publishes the prefixes it has already proven
  while `main` is unchanged. A review step pins the implementation range from
  the platform's recorded SHAs rather than from SHAs an agent typed.
- **A phone reaches every control.** The console has a phone shell — sticky top
  bar, five-slot tab bar, bottom sheet for the rest — and every page was read at
  390x844 and made to fit, with 44px touch targets and a chart geometry that is
  legible at 306px. On the desktop, an operator can lift a task's run budget and
  edit its prompt from the task page instead of reaching for the API.
- **The API refuses to start without `GITHUB_READ_TOKEN`.** It exits 78 and
  names the reason. The credential is read-only, is never exchanged with the
  merge token, and is now required of every API process. Obtain one before you
  run the install sequence.

The full list, by area, is in [`CHANGELOG.md`](../../CHANGELOG.md).

## Install and upgrade

There is no supported upgrade path between developer previews. This release
adds three migrations, so install fresh, following the quickstart in the
repository [`README.md`](../../README.md) — it checks out `v0.8.0`.

You need a read-only GitHub token for `GITHUB_READ_TOKEN` before you start: the
API refuses to boot without one in this release, whether or not you enable the
Direct or Full Assurance tiers.

Do not install this release over a v0.7.0 database. The supported release path
is `npm run db:migrate:release -- --fresh` against an empty schema. The host
warnings and verification steps in the
[Developer Preview quickstart](developer-preview.md) apply unchanged.

## Known limitations

- There is no supported in-place upgrade from v0.7.0. Install this preview
  against an empty schema through the fresh-install path above.
- The pull-request tier stops at an open pull request. Anneal does not review or
  merge it for you, and onboarding a project does not provision a second
  workflow or create a Secret.
- The `NO_CHANGES_PRODUCED` classification fixes the misleading delivery symptom
  reported in [Issue #305](https://github.com/mosonlab/anneal/issues/305), not
  the provider-side cause. A code-producing provider can still end a successful
  session after announcing work without writing or committing it. For a manual
  Task, the final prose remains available in Session events but is not promoted
  to retry handoff output.
- macOS on Apple Silicon and Linux (Ubuntu 24.04 LTS, x86_64) are the verified
  targets. macOS on Intel is expected to work but has not been exercised there;
  Windows is unsupported by design.
- The phone layout has known gaps that were left rather than half-fixed. The
  data tables — Agents, Projects, Connections, Secrets and the three Costs
  tables — still scroll horizontally instead of becoming card lists. The
  `Toggle` and `Check` controls keep their existing hit targets, because a hit
  halo on either would overlap the rows above and below in the stacked lists
  they appear in. iOS Safari zooms when you focus an input, because the whole
  application's type scale is pinned to a 13px root and the alternative,
  `maximum-scale=1`, would disable pinch zoom.
- Anneal still launches coding CLIs with the operator account's authority and
  is not a sandbox.

## Support, security and licensing

The [support matrix](support-matrix.md) remains the current statement of what is
supported and on what evidence. macOS on Apple Silicon is the target platform
and Linux is maintainer-verified; macOS on Intel is unverified and Windows is
unsupported. Anneal still launches coding CLIs with the operator account's
authority and is not a sandbox.

The [security](security.md), [license and assets](license-and-assets.md) and
[migration and recovery](migration-and-recovery.md) documents remain current.
